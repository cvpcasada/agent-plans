gh-postplan: project write-up

A small command-line tool that publishes a local HTML file to GitHub Pages, returns a stable public URL, and keeps every older version accessible.

npm: gh-postplan@0.1.0 TypeScript Node.js 22.18+ Bun development workflow Zero runtime dependencies

What we built

One-command publishing

npx gh-postplan publish ./draft.html pushes HTML and prints a shareable URL.

Version history

Each changed publish creates a permanent numbered URL while the stable draft URL moves forward.

Repository setup

Setup can configure an existing repository or explicitly create a new public repository.

Agent workflow

The npm package includes a skill that teaches agents how to create, publish, and read safe HTML drafts.

Core workflow

1. Read HTMLAccept one regular .html file.
2. Sync GitPull the dedicated gh-pages branch.
3. VersionWrite current and permanent copies.
4. VerifyPush, poll Pages, print the stable URL.
npx gh-postplan setup owner/pages-repo --create
npx gh-postplan publish ./draft.html

# Stable URL
https://owner.github.io/pages-repo/drafts/a1b2c3/

# Permanent versions
https://owner.github.io/pages-repo/drafts/a1b2c3/v1/
https://owner.github.io/pages-repo/drafts/a1b2c3/v2/

Behavior and decisions

AreaDecisionReason
Draft identityShort random ID, mapped from absolute source path locallyRepeat publishes keep one stable URL without exposing filenames.
Source of truthThe Pages repository determines the next versionLocal state can be lost or stale without overwriting history.
Unchanged filesNo new commit or versionAvoid empty history and pointless deployments.
DeploymentBranch-based Pages from gh-pagesNo workflow file or build service is needed for static HTML.
HTML policyPublish bytes unchangedThe tool has one owner and does not pretend to be a security scanner.
RuntimeCompiled JavaScript with no runtime packagesWorks through npx while TypeScript remains the source language.
ConcurrencyPull first, retry one rejected pushCovers two terminals without adding locks or a queue.

Commands

# Configure an existing repository
npx gh-postplan setup owner/pages-repo

# Create and configure a new public repository
npx gh-postplan setup owner/pages-repo --create

# Publish or update the draft associated with this file
npx gh-postplan publish ./draft.html

# Force a separate draft ID
npx gh-postplan publish ./draft.html --new

# Reconnect a file after local state was lost
npx gh-postplan publish ./draft.html --draft a1b2c3

# Push without waiting for the public copy
npx gh-postplan publish ./draft.html --no-wait

What shipped

Package

gh-postplan@0.1.0 on npm, published with the latest tag.

Verification

Strict typecheck, three focused tests, bundled executable check, npm tarball install, and registry verification.

Package contents

Compiled CLI, README, package manifest, and the bundled gh-postplan agent skill.

Credential handling

The npm token is injected through a managed local environment. It is not stored in the package or repository.

Boundaries

Published HTML is public

GitHub Pages serves the rendered drafts publicly. Draft HTML must never contain credentials, private URLs, or confidential material.

Single-file input

Only the HTML file is uploaded. Assets must be inline, data URLs, or already hosted at public absolute URLs.

Deliberate non-features

No dashboard, deletion workflow, HTML sanitizer, custom backend, database, authentication service, or deployment action.

Current housekeeping

The npm authentication config and environment ignore rule exist locally and still need a normal Git commit if they should be tracked.

Snapshot prepared after the first npm release. The project follows a simple rule: HTML in, stable public URL out.
