Canvid PWA + companion extension MVP

Implementation note · September 2, 2026
Design revision · September 9, 2026

One app, two installs. Canvid can run as an installable hosted web app while delegating privileged Chrome APIs to a small companion extension. Existing Electron and full-extension paths remain intact.

Hosted PWA

Owns the app and media

React UI, media processing, project state, OPFS storage, network requests, and normal browser APIs.

Installed companion

Owns privileged Chrome calls

Desktop capture selection, system information, and Chrome window control. Nothing more.

1. The boundary that matters

Before

Assumes an extension page

  1. 1recording.start()
  2. 2chrome.windows.getCurrent()
  3. 3chrome.windows.update(...)

Fails in a PWA: chrome.windows is absent.

After

Route privileged work

  1. 1recording.start()
  2. 2minimizeCurrentChromeWindow()
  3. 3PWA → companion message
  4. 4companion → sender window
  5. 5extension page → direct API

Existing full-extension behavior is retained.

2. Implemented bridge actions

The PWA knows the companion ID up front and performs a startup handshake. A missing or rejected connection renders the extension-required screen instead of starting half-connected.

ActionPurposeScope and safety
pingStartup handshake and extension presence check.Shows the extension-required screen if the call fails.
choose-desktop-mediaOpens Chrome's screen, window, or tab picker.Bound to the external message sender tab.
system-displayReturns display geometry and scaling.Read-only system API.
system-cpu / system-memoryReturns browser-visible device information.Read-only system APIs.
minimize-current-windowMinimizes Canvid when recording starts.Can only target the sender tab's window.
get-current-windowDetects restoration and preserves recording auto-stop behavior.Can only read the sender tab's window.

3. Build and development workflow

Local development

pnpm dev:pwa

Companion first
Build dist-companion, then load it unpacked in Chrome or Helium.
Vite on loopback
Open 127.0.0.1:5173. The stable companion ID and http://127.0.0.1/* allowlist are supplied automatically.
Production artifacts

Two separate outputs

pnpm build:pwa
dist-pwa → HTTPS hosting
pnpm build:companion-ext
dist-companion → extension distribution

After companion changes, rebuild and reload the unpacked extension. After environment changes, restart Vite and reload the PWA. Installing the PWA remains a separate browser action.

4. Identity and connection rules

  1. The companion manifest contains a stable public key, giving unpacked development builds a deterministic extension ID.
  2. The PWA calls that exact ID. A Web Store ID can replace it through VITE_COMPANION_EXTENSION_ID.
  3. externally_connectable.matches limits which PWA origin can call the extension.
  4. The extension cannot initiate first contact. Canvid performs the handshake during startup.

7. Known MVP limits

Still follow-up work

This is a connected PWA, not a web-only recorder.

Users must install both the PWA and companion extension. The PWA cannot install the extension silently.

  • •The service worker establishes installability but does not cache the full app for offline use.
  • •Chrome Web Store packaging, install guidance, update rollout, and release automation remain.
  • •Production extension ID and final hosted origin must be set during release packaging.

8. Recommended next slice

  1. Exercise one complete recording in PWA mode: choose source, record, restore, stop, edit, export.
  2. Add an install link and clearer recovery UI to the extension-required screen.
  3. Publish a private or unlisted companion build and lock the production origin and ID.
  4. Only then decide whether offline asset caching is worth its update complexity.
