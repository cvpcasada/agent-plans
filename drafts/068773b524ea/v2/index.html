Chrome Extension Permission Audit

Canvid for SkoleTube · updated from main at commit 33671554 · 2 September 2026

Main already fixed the store blockers. Version 3.1.2 removes declarativeNetRequest, declarativeNetRequestWithHostAccess, scripting, and webRequest. Their old GCS workaround and static CORS rule were deleted. Of the five permissions in the store warning, only unlimitedStorage remains and needs a justification.

Current result

Removed on main

declarativeNetRequest

No longer declared or used. The static gcs-cors.json ruleset was deleted because the SkoleTube extension no longer talks directly to Google Cloud Storage.

No Chrome Web Store justification needed for the new build.

Removed on main

declarativeNetRequestWithHostAccess

No longer declared or used. It existed for the same deleted Google Storage response-header rule.

No Chrome Web Store justification needed for the new build.

Removed on main

scripting

No longer declared or used. The old fallback injected a download into a Canvid web-app tab to work around Google Storage CORS. Downloads now use a normal same-host fetch.

No Chrome Web Store justification needed for the new build.

Removed on main

webRequest

No longer declared or used. The service worker no longer watches Google Storage upload completion events.

No Chrome Web Store justification needed for the new build.

Still used · justification required

unlimitedStorage

Still declared at chrome-ext/manifest.json:22. Canvid stores projects, recordings, media, and avatars in the Origin Private File System and requests persistent storage during startup.

Call site: src/bridge-shim.ts:90–119

Canvid stores video projects, recordings, media, and generated assets locally using the Origin Private File System. These files can exceed normal browser storage quotas and must be protected from automatic eviction.
