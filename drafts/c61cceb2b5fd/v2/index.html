Canvid PWA + Companion Extension MVP

The source report describes Canvid running as an installable hosted web app while delegating privileged Chrome APIs to a small companion extension. The existing Electron and full Chrome extension paths remain intact.

Decision

App responsibility

The hosted PWA owns React UI, media processing, project state, OPFS storage, network requests, and normal browser APIs.

Extension responsibility

The companion owns only APIs unavailable to a normal web page: desktop capture selection, system information, and Chrome window control.

Build and development workflow

Local development

pnpm dev:pwa

This first rebuilds the localhost companion, then starts the PWA at 127.0.0.1:5173. Load dist-companion as an unpacked extension and reload it after service-worker changes.

Production artifacts

pnpm build:pwa
pnpm build:companion-ext

The artifacts are written separately to dist-pwa and dist-companion, so neither package accidentally contains the other.

Identity and connection rules

  1. The companion manifest contains a stable public key, which gives unpacked development builds a deterministic extension ID.
  2. The PWA calls that exact extension ID. A Web Store ID can replace it through VITE_COMPANION_EXTENSION_ID.
  3. externally_connectable.matches limits which PWA origin can call the extension.
  4. Local development uses http://127.0.0.1/*. Production uses the configured HTTPS app hostname.
  5. The extension cannot initiate first contact. Canvid performs the handshake during startup.

Known MVP limits

This is a connected PWA, not a standalone web-only recorder. Users must install both the PWA and companion extension. The PWA cannot install the extension silently.
  • The service worker establishes installability but does not cache the full app for offline use.
  • Extension service-worker changes require reloading the unpacked extension during development.
  • The production extension ID and final hosted origin must be set as part of release packaging.
  • Chrome Web Store packaging, install guidance, update rollout, and end-to-end release automation remain follow-up work.
